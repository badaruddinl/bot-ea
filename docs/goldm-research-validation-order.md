# GOLDM research validation order

This ordering is mandatory for future REVISED and bear experiments unless the
user explicitly changes it.

## 1. Initial three partial checks

Run the unchanged candidate on all three windows first:

1. January 2025 through the latest available closed bar;
2. November 2025 through 15 February 2026;
3. June 2026 through the latest available closed bar.

Do not tune before recording all three results.

## 2. Development/tweaking window

Only when the candidate is not good enough on the initial partial checks, use
4–19 August 2026 to diagnose evidence and tune the algorithm.

The August window is development evidence, not blind/OOS validation. Tuning
must be causal and based on explicit chart/path evidence, not an hour, score,
or result filter chosen only because it improves aggregate profit.

## 3. Repeat the same three partial checks

After finding a promising August adjustment, rerun the exact frozen candidate
on the same three partial windows. No parameter may change between those three
runs.

If any required partial window remains unacceptable, return to diagnosis; do
not proceed to the full suite.

## 4. Full suite last

Run 2020 through the latest available closed bar only after the adjusted
candidate is good on all three repeated partial checks.

The full suite is a final stress/regime test, not a tuning source. A full-suite
result must not be used to silently retune the candidate and then reported as
validation.

## 5. Forward status

Passing these historical stages does not automatically authorize production
replacement or live orders. The candidate remains research/shadow-only until
the separately agreed execution-cost and forward-test gates pass.

## Required reporting

For every stage report at least:

- trade count and overlap/skip count;
- TP, SL, ambiguity, and unresolved outcomes;
- total R, expectancy, and maximum R drawdown;
- cash path for the explicitly requested balance/lot, when applicable;
- structural support/resistance/psychological violations;
- look-ahead, timestamp, duplicate, IPC, and execution failures;
- the frozen configuration identifier/hash used by every window.
